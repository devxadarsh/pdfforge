9. PDF RENDERING ENGINE

Use ngx-extended-pdf-viewer as the application's PDF viewing/rendering layer.

Requirements specific to the viewer:

Use the Angular component provided by ngx-extended-pdf-viewer instead of creating a custom PDF.js viewer.

Use the library's supported inputs, outputs, APIs, and lifecycle events for page navigation, zoom, rotation, fullscreen, thumbnails/sidebar, find/search, and document lifecycle.

Centralize common viewer configuration so behavior remains consistent across the application.

Synchronize Angular editor state with the viewer through supported library events and APIs.

Do not directly manipulate the viewer's internal PDF.js DOM or internals unless explicitly required by the library's documented API.

Keep PDF mutation and export responsibilities outside the viewer layer, primarily using pdf-lib where supported.

When a feature is already provided by ngx-extended-pdf-viewer, use the library capability instead of recreating it manually.

Verify compatibility between the project's Angular version and the selected ngx-extended-pdf-viewer version before installation.

Requirements:

Render pages correctly

High DPI rendering

Zoom

Fit width

Fit page

Scroll

Page navigation

Lazy rendering for large PDFs

Thumbnail rendering

Search support

Responsive rendering

Do not render 500 PDF pages simultaneously if it can be avoided.

Use virtualization/lazy rendering where practical.

The UI may present the feature as “Edit Text” where appropriate, but implementation must remain technically honest.
